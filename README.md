# Поиск выбросов и генерация новых признаков

Домашнее задание к занятию **«Поиск выбросов и генерация новых признаков»**: классификация типа стекла и исследование влияния выбросов на качество модели `RandomForestClassifier`.

Автор: **Александра Бужор** · Telegram: [@Angry_C_F_O](https://t.me/Angry_C_F_O)

## Данные

[Glass Identification](https://archive.ics.uci.edu/ml/datasets/Glass+Identification) (UCI, на Kaggle — *Glass Classification*): 214 образцов стекла, 9 признаков — коэффициент преломления `RI` и содержание оксидов `Na, Mg, Al, Si, K, Ca, Ba, Fe` (вес. %). Целевая переменная `Type` — 6 классов (класс 4 в данных отсутствует): окна зданий (float / non-float), окна автомобилей, тара, посуда, фары.

## Что сделано

1. **Первичный анализ**: пропусков нет, удалён 1 полный дубликат (214 → 213). Сильный дисбаланс классов: 68 % — окна зданий (классы 1 и 2), посуда — всего 9 записей.
2. **Разбиение** 80/20 со стратификацией (170 / 43), тест зафиксирован для обеих моделей.
3. **Модель 1** — `RandomForestClassifier` на исходных данных.
4. **Распределения**: `sns.boxplot`, `sns.histplot(kde=True)` (замена устаревшего `sns.distplot`), Q–Q графики, тесты Шапиро–Уилка и Д'Агостино–Пирсона. Нормально распределённых признаков нет; ближе всего — `Na`, `Al`, `Si`. `Mg` бимодален, `K`, `Ba`, `Fe` — с избытком нулей.
5. **Поиск выбросов пятью способами**: IQR (правило Тьюки), Z-оценка (3σ), Isolation Forest, Local Outlier Factor, Isolation Forest внутри каждого класса. Для каждого посчитан процент помеченных записей по классам.
6. **Удаление выбросов** (Isolation Forest по классам) только из обучающей выборки: 11 записей (6.5 %), по классам — от 4.9 % до 14.3 %.
7. **Модель 2** на очищенных данных, сравнение на том же тесте + повторная кросс-валидация 5×10 с очисткой внутри обучающих фолдов.

## Результаты

| Модель | Записей в обучении | Accuracy | Balanced accuracy | Macro-F1 |
|---|---|---|---|---|
| 1 — исходные данные | 170 | **0.8605** | 0.8437 | 0.8318 |
| 2 — без выбросов (Isolation Forest по классам) | 159 | **0.8372** | 0.8325 | 0.8198 |

Кросс-валидация 5×10 (accuracy, среднее):

| Способ очистки | Accuracy | Δ к базовой, п.п. |
|---|---|---|
| Без удаления | 0.782 | — |
| IQR (1.5·IQR) | 0.595 | −18.6 |
| Z-оценка (больше 3σ) | 0.765 | −1.7 |
| Isolation Forest | 0.775 | −0.7 |
| LOF | 0.768 | −1.4 |
| Isolation Forest по классам | 0.788 | +0.6 |

## Главные выводы

- **Глобальное правило IQR опасно на этих данных**: оно помечает 36.6 % записей, в том числе 100 % фар и 85 % тары. Признаки `Ba`, `Mg`, `K` с избытком нулей делают «выбросом» любую запись редкого класса.
- **Для случайного леса удаление выбросов не даёт значимого прироста**: на тесте модель 2 ошиблась на одну запись больше (−2.3 п.п.), на кросс-валидации лучший способ даёт +0.6 п.п. при разбросе около 6 п.п. Деревья делят выборку по порогам и устойчивы к экстремальным значениям признаков.
- **Удалять выбросы из всего датасета до разбиения нельзя**: тест становится другим и «облегчённым», появляется утечка, а после IQR из данных полностью исчезает класс «фары» — при этом accuracy выглядит высокой (0.85).
- Исследовать данные на выбросы нужно всегда, а удалять — только осознанно: ошибки измерений исправлять, редкие реальные значения оставлять; детектор обучать только на train и с учётом класса.
